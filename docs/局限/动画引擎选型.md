# 局限:动画为什么没用 Flame

记录日期:2026-10-11(动画引擎落地时定下的)

背景:这个 App 的主要教学内容就是动画(倒水、鸡蛋起落、盐水变色)。
Flame 是 Flutter 上最现成的 2D 游戏引擎,第一反应就是用它。最后没用,
self 写了一套声明式的积木 + 补间(见 `app/lib/engine/`)。

## 已定量、原因已知的

### 循环动画会让 `pumpAndSettle` 永远不返回

- 现象:一个一直在跑的 `AnimationController`(比如呼吸高亮)会让
  `tester.pumpAndSettle()` 一直泵下去,直到超时
- 出处:2026-10-11 实测。`SceneView` 里那段"高亮呼吸"就是重复动画,
  学环节的测试**只能**按秒 `pump(Duration(...))`,不能用 `pumpAndSettle`
  (`app/test/learn_page_test.dart` 开头有注释)
- 已定因:`pumpAndSettle` 的定义就是"一直泵到没有待处理的帧";只要有一帧接一帧
  排下去的动画,它就永远等不到"没有帧"的那一刻。**这是测试框架的语义,不是 bug**

### 这台机器上,截图是唯一"眼睛"

- 现象:没有模拟器、没有浏览器,`flutter run` 起不来 —— 界面对不对全看
  `flutter test --update-goldens` 出的 PNG(另见 `docs/局限/界面截图.md`)
- 已定因:golden 比对要的是"整棵树静下来、拍一张",这跟循环动画天然冲突
  (见上一条)
- 影响:凡是一进页面就不停跑的动画,都会把这条通道堵死

### 结论:Flame 的 `GameWidget` 正好是这一类

- 判断:`GameWidget` 由引擎自己驱动 ticker,页面一挂上就持续重绘
- **注意这一条是推理,不是实测**:没真把 flame 装进来跑一遍。推理的依据是本仓库
  自己那条实测(上面的呼吸高亮)—— 同一类机制
- 处理:v1 的动画是**声明式**的 —— 内容包里写"第几步第几秒水涨到 0.7",
  引擎把它编译成时间轴,播完就停。停得下来,截图通道就还在
- 附带好处:积木是数据不是代码,加一个知识点 = 加一个内容包,不用动引擎
  (这也是设计文档里那条"内容包"的初衷)

## 没验的(别当已知)

- **装上 Flame 之后 `pumpAndSettle` 到底会不会挂**:上面那条是推理。真要换引擎,
  第一件事应该是写个最小用例实测一下,而不是照着这份文档下结论
- **Flame 有没有办法临时关掉 ticker**:比如只在外层套一个静态的 `CustomPaint` 复用它
  的绘制层。没查过
- **复杂动画以后够不够用**:现在的积木只有五块、都是平涂矢量。
  要是哪天要做粒子、物理碰撞,自研这套会不够 —— 那时候再评估
