# 小言数学乐园（xiaoyan）设计文档

日期：2026-10-08
状态：已与用户逐批确认（架构 / 游戏化·语音·视觉·存储 / 结构·工具链·规范·测试），本文为成稿。

## 1. 背景与目标

给小学生（用户女儿）的数学动画学习 Android 应用：她不懂的题目，由用户转换成动画内容，让她在 App 里"学—练"。核心价值是**内容生产回路快**——从"发现她不会"到"她能在手机/平板上玩到对应内容"的距离要短。

先给自家用；架构预留发布扩展空间（内容与代码分离、数据层走 repository 接口）。纯单机，无后端，无账号。

## 2. 核心工作流

```
她的错题/作业
   →（用户 + Claude 协作）写内容包 topic.json + 逐句文案
   → tools/ 脚本生成龙呼呼语音 mp3
   → 内容包校验（schema + 音频齐全性 + 积木引用存在性）
   → 打包进 App，女儿学—练
   → 练习错题自动入错题本
   → 错题记录成为下一轮内容生产的输入
```

## 3. 技术选型

- **Flutter + Flame**：全程游戏化需要拖拽、碰撞、粒子、音效，Flame 是专为 2D 小游戏设计的引擎；一套代码将来可发 iOS。用户明确选定（在了解 study 参考项目之后重新确认过）。
- **参考项目 `~/Desktop/work/study`（数学乐园 Web 版）只取两样**：
  - 视觉风格：animal-island-ui 的动森风格基因（奶油底、大圆角、动森绿暖黄）
  - 语音方案：阿里云 CosyVoice `longhuhu_v3`（龙呼呼童声，6-10 岁女童音色）的生产方式
  - **其中的 5 个知识点内容不迁移**，内容全部按女儿实际情况重新开发。

## 4. 总体架构

```
┌─────────────────────────────────────────┐
│  壳层 (Flutter widgets)                  │
│  首页知识点地图 · 错题本 · 设置 · 结算页    │
├─────────────────────────────────────────┤
│  学-练引擎 (Flame)                        │
│  学：执行内容包的声明式动画时间线 + 语音同步 │
│  练：交互模板（拖拽/点选/连线/填空）+ 判题   │
├─────────────────────────────────────────┤
│  积木层（可复用动画/交互组件）              │
│  小棒·数轴·格子·切割·分组·计数·高亮·粒子…  │
├─────────────────────────────────────────┤
│  内容包（纯数据 assets/content/**）        │
│  topic.json（步骤+题目+文案+音频引用）      │
├─────────────────────────────────────────┤
│  本地数据 (Hive, repository 接口)          │
│  进度·星星·错题·设置                       │
└─────────────────────────────────────────┘
```

核心原则（即"方案 C"）：
- **加一个知识点 = 加一个内容包（数据 + 音频），不改引擎代码**
- 内容包表达不了的新动画/新交互 → 往积木层加一块新积木（一次性投入，永久复用）

## 5. 内容包设计

一条内容包 = `app/assets/content/<slug>/` 目录：

- `topic.json`：元信息（slug/标题/年级/分类/难度/emoji）、`learn.steps`（动画步骤序列，每步引用积木 + 参数 + 逐句文案 + 音频文件名）、`practice.items`（题目集，每题引用交互模板 + 题目数据 + 提示文案）
- `audio/s01.mp3, s02.mp3, …`：龙呼呼按句预生成的语音，与步骤一一对齐

`topic.json` 的 JSON Schema 放 `content-schema/`，作为用户与 Claude 的共同契约；草案随冒烟示例包落地，随第一个真实内容包打磨定型。

**内容不预设**：本设计不做任何内容选题规划；v1 只带 1 个最小示例包做链路冒烟（证明数据→动画→语音→判题跑通），真实内容全部由用户按女儿作业与反馈决定。

## 6. 学—练—反馈闭环

每个知识点固定三段式：

1. **学**：龙呼呼语音 + 动画演示；可暂停/重播/上一步
2. **练**：交互题若干；做对→星星 + 彩带粒子 + 随机夸奖语音；做错不惩罚——温柔提示（轻抖动 + 高亮线索），可重试；连错 3 次自动跳回"学"的对应步骤重看再回来
3. **反馈**：结算页星星汇总；错题自动入错题本（首页有"错题重练"入口，也是用户下轮出内容的素材来源）

## 7. 游戏化机制

- 星星：每题一次做对得 ⭐，结算页汇总，飞入首页进度徽章
- 限时挑战：默认关闭（低年级不制造焦虑），内容包按知识点可选开启
- 反馈基调：只奖励不惩罚，错误是"再试一次"而不是"失败"

## 8. 语音方案

- 生产侧：`tools/` 脚本调 DashScope CosyVoice（`cosyvoice-v3-flash` + `longhuhu_v3`），按 topic.json 逐句文案批量生成 mp3；**API Key 只存用户电脑的环境变量，绝不进仓库、不进 App**（.gitignore 覆盖 .env*）
- App 侧：完全离线播放，音频随内容包打包
- 兜底：某句音频缺失时用安卓系统 TTS 播该句，保证永远有声音（校验工具同时警告缺失）
- 预置少量公开版权通用音效（点击/成功/失败）

## 9. 视觉风格（动森风）

落成 `lib/theme/design_tokens.dart` 统一管理：

- 奶油/米白底色，大圆角卡片（16-24px），动森绿 + 暖黄 + 天蓝点缀，粗描边 + 软阴影
- 数字用 Nunito 圆体，中文系统字体加粗大字号；大按钮大间距（儿童手指）

## 10. 数据存储

- Hive：知识点进度/星星、错题记录、设置
- 数据访问一律走 repository 接口，将来发布加云同步时换实现不动上层

## 11. 手机 + 平板适配

- 同一 APK 兼容手机和平板
- 首页网格自适应列数（手机 2 列 / 平板 4-5 列）；Flame 场景固定逻辑分辨率等比缩放，两种屏幕共用一套内容
- 横竖屏都支持；手机竖屏优先优化，平板横屏优先优化

## 13. 工具链与仓库位置

- 仓库从 `/mnt/c/...` 挪进 WSL 文件系统（`~/src/...`）：`/mnt/c` 上 Flutter 构建慢 5-10 倍
- WSL 安装 Flutter SDK + Android cmdline-tools（Java 17 已有，KVM 可用，模拟器可跑）；真机装 debug APK 最省事
- Windows 侧 IDE 可经 `\\wsl$` 路径打开同一仓库

- 全局 CLAUDE.md 的开发流程（先看资料→说思路→确认→动手）写入项目 CLAUDE.md

## 15. 测试策略

- 内容包校验（最重要）：schema + 音频齐全性 + 积木/模板引用存在性，打包前必须过
- 判题逻辑单元测试；关键积木组件测试；不追覆盖率，测"改得动"的部分

## 16. v1 范围与非目标

**v1 交付**：Flutter 工程骨架 + 学练引擎 + 首批积木 + 内容包管线（schema/校验/音频脚本）+ 1 个最小示例冒烟包 + 手机/平板可安装。

**非目标（v1 明确不做）**：后端/账号/云同步、真实内容选题规划、iOS、内购、多孩子档案。

## 17. 已知约束与风险

- 本机尚无 Flutter/Android 工具链，需从零安装（WSL 方案已验证 KVM 可用）
- CosyVoice 音色质量依赖 DashScope 服务可用性；生产在 PC 侧完成，不影响 App 运行
- Flame 时间线执行器是自研核心件，设计偏简单（顺序步骤 + 少量并行），复杂编排按需演进
