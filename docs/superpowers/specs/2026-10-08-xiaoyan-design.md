# 小妍乐园（xiaoyan）设计文档

日期：2026-10-08（初稿）／2026-10-10（修订：加入科学小实验模块，应用更名「小妍乐园」）
状态：已与用户逐批确认（架构 / 游戏化·语音·视觉·存储 / 结构·工具链·规范·测试 / 科学模块形态·v1 范围·命名·实验记录），本文为成稿。

## 1. 背景与目标

给小学生（用户女儿小妍）的动画学习 Android 应用，两个模块：

- **数学乐园**：她不懂的题目，由用户转换成动画内容，让她在 App 里"学—练"
- **科学小实验**：动画讲原理 → 拿家里的东西动手做 → 拍下来，目标是**养兴趣、开视野**，不追求掌握度

核心价值仍是**内容生产回路快**——从"发现她不会 / 她对什么好奇"到"她能在手机/平板上玩到对应内容"的距离要短。两个模块共用同一条内容生产线。

先给自家用；架构预留发布扩展空间（内容与代码分离、数据层走 repository 接口）。纯单机，无后端，无账号。

## 2. 核心工作流

两条内容回路，共用一套工具链：

```
【数学】
她的错题/作业
   →（用户 + Claude 协作）写内容包 topic.json + 逐句文案
   → tools/ 脚本生成龙呼呼语音 mp3
   → 内容包校验（schema + 音频齐全性 + 积木引用存在性）
   → 打包进 App，小妍学—练
   → 练习错题自动入错题本
   → 错题记录成为下一轮内容生产的输入

【科学】
她的好奇/提问、生活里的现象（下雨、影子、泡泡…）
   →（用户 + Claude 协作）写实验包：原理动画步骤 + 材料清单 + 安全提示 + 分步引导 + 现象选项
   → tools/ 脚本生成语音 mp3（原理句 + 实验引导句）
   → 同一套校验
   → 打包进 App，小妍学原理—动手做—拍照记录
   → 照片与现象进"我的实验册"，连同她后续的提问，成为下一轮内容生产的输入
```

## 3. 技术选型

- **Flutter + Flame**：全程游戏化需要拖拽、碰撞、粒子、音效，Flame 是专为 2D 小游戏设计的引擎；一套代码将来可发 iOS。用户明确选定（在了解 study 参考项目之后重新确认过）。科学模块沿用同一选型——液体、气泡、颜色变化同样是 2D 动画 + 粒子。
- **参考项目 `~/Desktop/work/study`（数学乐园 Web 版）只取两样**：
  - 视觉风格：animal-island-ui 的动森风格基因（奶油底、大圆角、动森绿暖黄）
  - 语音方案：阿里云 CosyVoice `longhuhu_v3`（龙呼呼童声，6-10 岁女童音色）的生产方式
  - **其中的 5 个知识点内容不迁移**，内容全部按小妍实际情况重新开发；该项目的 5 个知识点全是数学，**科学模块没有可抄的参考，要全新设计**

## 4. 总体架构

```
┌──────────────────────────────────────────────┐
│  壳层 (Flutter widgets)                       │
│  首页：数学乐园 / 科学小实验 两个入口             │
│  知识点地图 · 结算页 · 错题本                    │
│  实验列表 · 实验册（照片 + 现象）                 │
├──────────────────────────────────────────────┤
│  学—做引擎 (Flame)                             │
│  学：执行内容包的声明式动画时间线 + 语音同步        │
│  做：数学→交互模板 + 判题；科学→分步引导 + 记录     │
├──────────────────────────────────────────────┤
│  积木层（可复用动画/交互组件）                    │
│  数学：小棒·数轴·格子·切割·分组·计数·高亮·粒子      │
│  科学：容器·液体·粉末倒入·气泡·颜色混合·倾倒·天平    │
├──────────────────────────────────────────────┤
│  内容包（纯数据 assets/content/**）              │
│  topic.json（kind: math | science）             │
├──────────────────────────────────────────────┤
│  本地数据 (Hive, repository 接口)                │
│  进度·星星·错题·实验记录·设置                     │
└──────────────────────────────────────────────┘
```

核心原则（即"方案 C"）：

- **加一个知识点 / 一个实验 = 加一个内容包（数据 + 音频），不改引擎代码**
- 内容包表达不了的新动画/新交互 → 往积木层加一块新积木（一次性投入，永久复用）

两个模块**共用**引擎、积木注册表、音频管线、存储接口；差别只在**积木集合**与**内容包的分叉字段**（数学走 `practice`，科学走 `experiment`）。

## 5. 内容包设计

一条内容包 = `app/assets/content/<slug>/` 目录，顶层 `kind` 决定它属于哪个模块。

公共部分（两类包都有）：

- 元信息：`slug` / `title` / `grade` / `category` / `difficulty` / `emoji` / `kind`
- `learn.steps`：动画步骤序列，每步引用积木 + 参数 + 逐句文案 + 音频文件名
- `audio/s01.mp3, s02.mp3, …`：龙呼呼按句预生成的语音，与步骤一一对齐

分叉部分：

- `kind: "math"` → `practice.items`：题目集，每题引用交互模板 + 题目数据 + 提示文案
- `kind: "science"` → `experiment`：
  - `materials`：材料清单（名称 + 用量 + 家里有没有）
  - `safety`：安全提示（**校验强制非空**）
  - `steps`：动手步骤（文案 + 音频 + 图示积木），孩子做完一步点"下一步"
  - `recordOptions`：现象选项（id + 文案 + emoji，如"冒泡了 🫧"）
  - `adultNote`：给家长的备料/陪同提示（可选）

`topic.json` 的 JSON Schema 放 `content-schema/`，作为用户与 Claude 的共同契约：**一份 schema，按顶层 `kind` 分支**（公共字段只定义一次，校验工具单点）。已随「盐水浮鸡蛋」冒烟包落地：`content-schema/topic.schema.json`（内容包结构，学环节的步骤是 `bricks` 数组，一步可含 1..n 块积木）+ `content-schema/bricks.json`（积木注册表契约，内容包引用的积木必须先在这里登记）。随第一批真实内容包继续打磨定型。

**内容不预设**：本设计不做任何内容选题规划；v1 只带 1 个数学最小示例包 + 1 个科学冒烟实验包做链路冒烟（证明数据→动画→语音→判题/记录跑通），真实内容全部由用户按小妍的作业、提问与反馈决定。

## 6. 学习闭环

两个模块各有一条固定三段式。

**数学：学—练—反馈**

1. **学**：龙呼呼语音 + 动画演示；可暂停/重播/上一步
2. **练**：交互题若干；做对→星星 + 彩带粒子 + 随机夸奖语音；做错不惩罚——温柔提示（轻抖动 + 高亮线索），可重试；连错 3 次自动跳回"学"的对应步骤重看再回来
3. **反馈**：结算页星星汇总；错题自动入错题本（首页有"错题重练"入口，也是用户下轮出内容的素材来源）

**科学：学—做—记**

1. **学**：原理动画 + 龙呼呼语音，讲清"为什么会这样"（如小苏打遇醋冒泡 = 产生了二氧化碳）；可暂停/重播/上一步
2. **做**：材料清单 → 安全提示页（全屏，要求大人陪同）→ 分步引导，每步一句语音 + 图示，小妍做完一步点"我做好了，下一步"；不判对错、不设倒计时
3. **记**：拍照 + 从 `recordOptions` 点选自己看到的现像 → 盖完成印章 + 一颗星星，照片与现象进"我的实验册"

科学模块 v1 **不设判题与测验**：目标是兴趣不是掌握度，现象跟预期不一样也照样算完成。

## 7. 游戏化机制

- 星星：数学每题一次做对得 ⭐，结算页汇总；科学每个实验做完得 ⭐；两边都飞入首页进度徽章
- 印章：每个科学实验完成盖一枚印章，进实验册，首页科学板块显示"已收集 N 枚"
- 限时挑战：默认关闭（低年级不制造焦虑），内容包按知识点可选开启（仅数学）
- 反馈基调：只奖励不惩罚，错误是"再试一次"而不是"失败"

## 8. 语音方案

- 生产侧：`tools/gen_audio.py` 调 DashScope CosyVoice（`cosyvoice-v3-flash` + `longhuhu_v3`），按 `topic.json` 逐句文案批量生成 mp3——数学生成 `learn.steps`，科学生成 `learn.steps` + `experiment.steps`；**API Key 只存用户电脑的环境变量，绝不进仓库、不进 App**（.gitignore 覆盖 .env*）
- **实测结论（2026-10-10，盐水浮鸡蛋冒烟包）**：端点是 `POST /api/v1/services/audio/tts/SpeechSynthesizer`，`voice` / `format` / `sample_rate` 放在 `input` 里（不是 `parameters`），返回 JSON 带一个 24 小时有效的音频地址；`longhuhu_v3` 直接可用，**不需要在百炼控制台额外开通**（`study` 里的相反注释是过时的）。输出定 **mp3**（22050Hz 单声道，约 128kbps），不用 wav：CosyVoice 的 wav 头 `data` 长度字段是占位值（实测 0x7FFFFFDB），播放器按它判断结尾会出错，且体积大 2.7 倍
- App 侧：完全离线播放，音频随内容包打包
- 兜底：某句音频缺失时用安卓系统 TTS 播该句，保证永远有声音（校验工具同时警告缺失）
- 预置少量公开版权通用音效（点击/成功/失败）

## 9. 视觉风格（动森风）

落成 `lib/theme/design_tokens.dart` 统一管理：

- 奶油/米白底色，大圆角卡片（16-24px），动森绿 + 暖黄 + 天蓝点缀，粗描边 + 软阴影
- 数字用 Nunito 圆体，中文系统字体加粗大字号；大按钮大间距（儿童手指）

**科学模块不做第二套视觉体系**，沿用同一套 token；两个板块靠入口卡片主题色区分（数学=动森绿，科学=天蓝）。

## 10. 数据存储

- Hive：知识点进度/星星、错题记录、**实验记录（slug / 完成时间 / 现象选项 id / 照片相对路径）**、设置
- 照片存 App 私有目录 `photos/<slug>-<时间戳>.jpg`，Hive 只存相对路径；删记录时一并删文件（图片不进 Hive）
- 数据访问一律走 repository 接口，将来发布加云同步时换实现不动上层

## 11. 手机 + 平板适配

- 同一 APK 兼容手机和平板
- 知识点地图与实验列表用自适应列数网格（手机 2 列 / 平板 4-5 列），实验册照片网格同样自适应；Flame 场景固定逻辑分辨率等比缩放，两种屏幕共用一套内容
- 横竖屏都支持；手机竖屏优先优化，平板横屏优先优化

## 13. 工具链与仓库位置

- 仓库只留 WSL 文件系统这一份：`~/src/github.com/chenniannian90/xiaoyan`（`/mnt/c` 上 Flutter 构建慢 5-10 倍，`/mnt/c` 那份已删）
- WSL 侧装的是 Flutter 3.47.7 stable + Android SDK 36（platforms / build-tools / ndk）+ JDK 17，licenses 已接受
- **开发期验收走「只出 APK」**（2026-10-10 用户定）：`flutter build apk --release --split-per-abi`，产物拷进手机装；不搭模拟器、不配 usbipd 真机调试
- Windows 侧 IDE 可经 `\\wsl$` 路径打开同一仓库

**实测：国内直连三个源都很慢，必须走镜像（2026-10-10）**

| 东西 | 官方源 | 换用的镜像 | 实测 |
|---|---|---|---|
| Flutter SDK / 引擎构件 | storage.googleapis.com | storage.flutter-io.cn | 27 MB/s（官方约 0.95 Mbps） |
| pub 包 | pub.dev | pub.flutter-io.cn | —— |
| Gradle 分发包 | services.gradle.org | mirrors.cloud.tencent.com/gradle | 26 MB/s（官方那条基本不动） |
| Maven 依赖 | google() / mavenCentral() | maven.aliyun.com/repository/{public,google,gradle-plugin} | 实测 200 |

写在哪（**新工程要照着改一遍，否则第一次构建会卡住**）：

- `~/.bashrc`：`FLUTTER_STORAGE_BASE_URL` / `PUB_HOSTED_URL`。这个同时决定 Flutter gradle 插件往仓库列表里加的 `download.flutter.io` 指向哪（插件源码 `FlutterPlugin.kt:91`），release 包缺的 `io.flutter:*_release` 构件就从这里取
- `android/gradle/wrapper/gradle-wrapper.properties`：`distributionUrl` 换腾讯镜像
- `android/settings.gradle.kts` 的 `pluginManagement.repositories` 与 `android/build.gradle.kts` 的 `allprojects.repositories`：阿里云三条放最前，官方源留在后面兜底

**环境层踩过的坑（2026-10-10）**

- 只装了 `openjdk-17-jre-headless`（JRE 无 javac），Gradle 报 `Toolchain ... does not provide the required capabilities: [JAVA_COMPILER]`；装 `openjdk-17-jdk-headless` 解决
- 补上 javac 后仍报同一个错：Gradle 守护进程在装 javac **之前**就起来了，把工具链探测结果缓存住了（默认存活 3 小时）。`./gradlew --stop` 杀掉后立刻正常——改环境变量/JDK 后要想着杀守护进程
- release 构建偶发失败在 `Could not GET https://dl.google.com/...`：网络抖动导致 Gradle 直接中止（不是 404 跳过），重跑一次即过。真构件来自 `storage.flutter-io.cn`，与 dl.google.com 无关
- 空工程 debug APK 144 MB（三 ABI + JIT）、release 分 ABI 后 12.7 / 15.5 / 16.9 MB——手机上装 release 那个（arm64），别装 debug

## 15. 测试策略

- 内容包校验（最重要）：两类包的 schema + 音频齐全性 + 积木/模板引用存在性 + 科学包 `safety` 非空，打包前必须过。已落地 `tools/validate_content.py`：查 schema、音频在不在、音频是不是真音频且时长合理、积木有没有登记、slug 对不对得上目录名；`--strict` 把警告也当失败（打包时用）。校验器本身用坏包验证过会红：缺音频、报错 JSON 冒充音频、引用未登记积木三种情况都能抓出来
- 判题逻辑单元测试；关键积木组件测试（数学、科学各至少一块）；不追覆盖率，测"改得动"的部分
- 实验记录链路：真机/模拟器上跑一遍"拍照 + 选现象 + 进实验册"；**无相机权限时降级为只选现象**要走一遍，且要有一个能先红后绿的验证方式

## 16. v1 范围与非目标

**v1 交付**

- Flutter 工程骨架
- 学—做引擎：时间线执行器 + 数学交互模板/判题 + 科学分步引导器
- 首批积木：数学一套（小棒/数轴/格子/切割/分组/计数/高亮/粒子）；科学按「盐水浮鸡蛋」冒烟包的实际需要定下 5 块：`shared.scene`（布景）/ `shared.highlight`（高亮）/ `science.liquid`（液体）/ `science.egg`（鸡蛋位置与浮沉）/ `science.pour`（倒盐 + 搅拌）。原计划里的「气泡」这个实验用不上，不提前做
- 内容包管线：两类 schema + 校验脚本 + 音频生成脚本
- 1 个数学最小示例包 + 1 个科学冒烟实验包
- 科学实验册最小闭环：拍照 + 现象选项 + 印章
- 手机/平板可安装

**非目标（v1 明确不做）**

后端/账号/云同步、真实内容选题规划、iOS、内购、多孩子档案；科学模块的判题与测验、实验过程录像、实验册分享/导出。

## 17. 已知约束与风险

- 本机尚无 Flutter/Android 工具链，需从零安装（WSL 方案已验证 KVM 可用）；仓库也需先从 `/mnt/c` 挪进 WSL
- CosyVoice 音色质量依赖 DashScope 服务可用性；生产在 PC 侧完成，不影响 App 运行
- Flame 时间线执行器是自研核心件，设计偏简单（顺序步骤 + 少量并行），复杂编排按需演进
- **科学积木表现力要求高于数学积木**（液体、气泡、颜色混合），开发成本更高；v1 只做冒烟包用得到的最小集，其余按真实内容需要增量，别一次铺开
- **拍照依赖 Android 相机权限**（manifest 声明 + 运行时申请）；未授权时记录页降级为"只选现象不拍照"，不阻断完成流程
- **儿童实验安全**：材料清单与安全提示需家长把关，App 只做提示、不担保；校验强制 `safety` 非空，动手前有家长陪同提示页
- 科学内容没有参考项目可抄，原理动画的表现方式需要在冒烟包里先试出来
